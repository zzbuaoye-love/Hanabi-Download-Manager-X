# NeoNSF 架构与迁移边界

状态：NeoNSF 1.0.0（控制协议 v2）
日期：2026-07-26

## 1. 产品边界

- NSFX 继续作为默认、稳定和长期兜底内核。
- Auto 是双内核自动路由模式；NSFX 与 NeoNSF 也都可以被单独指定。
- NeoNSF 是并行开发的新内核，当前版本 `1.0.0`，控制协议 `v2`。
- 切换只影响新任务；任务创建后由不可变 `kernelId` 绑定原内核。
- 不在运行中迁移任务，不让两个内核同时写同一个目标文件。
- 只有 Auto 可以在 NeoNSF 接收任务前回退 NSFX；显式选择 NeoNSF
  时不静默换核。原生侧确认接收后任何模式都不再自动换核。

## 2. 技术选择

NeoNSF 使用常驻 `.NET 8 NativeAOT` 侧车，而不是在 Dart 中继续堆叠
isolate，也不自研高复杂度网络协议栈。

- `HttpClient` / `SocketsHttpHandler`：连接池、TLS、HTTP/1.1、HTTP/2、
  HTTP/3、系统代理和显式代理。
- 原生异步 `FileStream` / `RandomAccess.WriteAsync`：直连和并行 Range
  字节直接写入 `.neonsf.partial`，不经过 Dart 数据面。
- JSONL stdin/stdout：Dart 只传控制命令并消费增量事件。
- NativeAOT：发布为单个 `HanabiNeoNSF.exe`，不要求用户安装 .NET。
- 传输实现保持 provider 边界，未来可以接入经过基准和维护性验证的库，
  不需要替换任务控制面与持久化协议。

## 3. 当前执行范围

NeoNSF 1.0.0 接收所有 HTTP/HTTPS 大小范围，且所有任务共用一条起手路径：

- 一次 `GET Range: bytes=0-` 同时得到长度、Range 能力、验证器和重定向后的
  最终 URL，响应体直接作为下载数据，**不存在独立的预探测往返**。
  已有断点状态时改用 `bytes=0-0` 仅校验验证器。
- `206` 且长度 ≥ 8 MiB 时进入分块并发，探测响应充当 lane 0 的第一个分块。
- 初始只规划一个覆盖全文件的分块，新车道上线时切走在途最大分块的尾巴；
  请求总数等于实际启用的车道数，为理论下限。
- 并发数由自适应调速器决定而非配置：1 条车道起步，1.5 s 热身后每 1.2 s 采样，
  吞吐提升 ≥ 15% 才升档，否则退回一档并停止。上限 `maxConnections`（≤ 16）。
- 每条车道独占一个 `SocketsHttpHandler`，保证 HTTP/2 下也是独立 TCP 连接。
- `200`、`416` 或服务端拒绝分段时收敛为单连接流式下载。
- 分块目标文件先 `FSCTL_SET_SPARSE` 再 `SetLength`，避免 NTFS 同步零填充。
- `.neonsf.state`（检查点 v2）保存分块列表、ETag、Last-Modified、总长度与最终 URL。
- 支持暂停/恢复、取消、分段级重试、SHA-256 校验、全局限速、并发闸门、代理、
  HTTP 版本策略、Referer、Cookie、User-Agent 和自定义 Header。

## 4. 双内核路由

`KernelManager` 是永久双内核路由器：

1. NSFX 始终启动，并持有唯一的浏览器扩展 HTTP 监听器。
2. NeoNSF 在 Auto/NeoNSF 被选择或检测到 Neo 历史任务时启动；NSFX
   模式下也可在切到 Auto 时无重启启动。
3. 浏览器 API、UI 和系统服务都通过 `KernelManager` 发命令。
4. 暂停、续传、取消、重命名和移动按任务 `kernelId` 返回原内核。
5. 任务列表、进度事件、完成事件和统计在路由层聚合。

NeoNSF 使用独立目录：`~/.hdmx/kernel/neo_nsf/`。存储 ID 保持不变以兼容
已有数据。任务状态和恢复所需的
请求 Header 一起持久化；重启时活动任务恢复为暂停，不会被 NSFX 误读。

## 5. 速度口径

速度只在原生接收并写入响应 body 的位置计算：

- `rawInstantBps`：单个采样区间的原始速度。
- `windowBps` / `instantBps`：250 ms 采样后的 EWMA 显示速度。
- `averageBps`：累计 wire bytes / active transfer time。
- `activeTicks`：不包含暂停和重试退避的活动传输时钟。

小文件在第一个显示窗口前完成时不伪造瞬时速度，只在完成事件提供真实
平均速度。

## 6. 稳定性规则

- partial 文件关闭后才原子替换最终文件；`expectedSha256` 存在时先校验再替换。
- Range 响应的起点、终点或资源总长度不匹配时清空重建，禁止拼接错误数据。
- 并行恢复必须通过 ETag 或 Last-Modified 验证；验证器变化时从零重建。
- 连接中断、读取超时、HTTP 408/429/5xx 可以退避重试。
- 分段级重试：单条车道失败只重试自己那一块并回收该车道连接；
  致命错误经链接取消令牌中止全部车道，不再让一次抖动毁掉整个任务。
- 慢车道熔断仅在 ≥ 2 条车道活跃时生效，单连接任务永不触发。
- 暂停、取消和重试退避共用请求级取消句柄，不销毁连接池。
- 失败、完成和取消的原生任务立即释放，允许同 ID 显式重试；
  `enqueue` 对已暂停的同 ID 任务等价于 `resume`，不再抛错。
- 检查点与进度分别由 1 秒和 250 ms 的独立定时器驱动，热路径无锁、无落盘。
- 所有区域敏感解析显式使用 `CultureInfo.InvariantCulture`。
- stdin/stdout 固定 UTF-8，不随控制台代码页变化，中文路径与错误消息始终正确。
- 侧车崩溃由 Dart 侧指数退避重启并按检查点自动重新入队；10 秒心跳检测无响应进程。
- 侧车接受 `--parent-pid`，宿主消失时自我终止，不留孤儿下载进程。
- 直连、系统代理和显式 HTTP/SOCKS 代理使用不同连接池键；直连启用 Happy Eyeballs。

## 7. 非复制原则

IDM、Ghost Downloader 3 和其他下载器只用于黑盒行为、公开协议事实和性能
方法论参考。NeoNSF 不复制它们的源码、类结构、调度器、任务格式、文件格式、
界面或命名。任何实现都必须由本项目自行设计，并可通过本仓库测试解释其行为。

## 8. 后续迁移顺序

已完成：跨任务并发闸门、检查点显式版本与批量刷盘节流、动态分块与慢连接拆分。

1. 增加**按主机**的并发预算和自适应降并发历史（当前闸门是全局的）。
2. 补崩溃注入测试：在写入与检查点之间强杀侧车，验证恢复不丢字节。
3. 公网性能回归基准（HTTP/2 CDN、高 BDP 链路、IPv6 劣化网络）。
4. 继续改进 NSFX，确保它始终是独立可用的稳定内核。
5. 只有当长期稳定性、恢复正确性和性能门槛都通过后，才讨论默认内核变更；
   当前默认仍为 NSFX。
